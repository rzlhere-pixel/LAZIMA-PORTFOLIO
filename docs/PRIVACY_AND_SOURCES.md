# Source, Attribution & Publishing Policy

**Public repository policy:** This repository contains only generic and approved-neutral project guidance. The complete source archive is intentionally withheld.

## Never include publicly without explicit review
- Identifiable portraits, private family media, photographs containing other people
- Personal phone/email/home address, IDs, certificates, full resumes or recruitment records
- Employer-owned designs, customer images, private orders, trackers, contracts, draft technical sheets
- Previously produced PDFs or PPTXs with embedded photos, private contact details or unverified claims
- Original artworks with unclear collaborator/photographer credits
- Tokens, API keys, authentication configuration or access links

## Evidence grading
- **Verified from original:** source file/date/approval is cited.
- **First-person reported:** directly stated by owner/subject; not independently documented.
- **From earlier drafts:** use only as a hypothesis until checked.
- **Unverified:** insufficient source or usage rights; cannot be published as a fact.
- **Reference:** borrowed design inspiration, not original work.

## Release gate
1. Confirm authorship and source provenance per asset.
2. Confirm photographer/designer/employer rights and required attribution.
3. Confirm the subject's approval for any identifiable image.
4. Verify role, dates, qualification, contribution and results from original evidence.
5. Review editable file, exported PDF, captions, sources and all contact details.
6. Secure explicit final publication approval.

## Private handoff
Set repository to **private** in GitHub Settings → General → Danger Zone → Change repository visibility. Review current collaborators/Claude access first. Then import **approved** source files; never treat changing to private as blanket permission to publish an employer's work.

Use [the blank asset register](ASSET_REGISTER_TEMPLATE.csv) for a traceable intake.
